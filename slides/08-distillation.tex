  \note<1>{
    \footnotesize
    Magic-state distillation is a standard building block for fault-tolerant
    quantum computation: combine many imperfect resource states to obtain a
    cleaner surviving resource. The diagram uses $\ket{\mathrm{CCZ}}$ as an
    example; the symbols indicate the intended state, and red indicates a
    faulty copy. For background, see
    \href{https://arxiv.org/abs/quant-ph/0403025}{Bravyi--Kitaev (2005)} and
    \href{https://arxiv.org/abs/1209.2426}{Bravyi--Haah (2012)}.
  }
  \note<2>{
    \footnotesize
    Distillation suppresses errors in quantum resources before we produce the
    final sample. Under its input-quality assumptions and with an honest
    implementation, recursive distillation can reduce inverse-polynomial
    resource error to negligible error using polynomial resources. This is
    the role of distillation in our construction, not a generic amplification
    theorem for arbitrary sampling-verification protocols. Details of our
    resource-error model and distillation analysis come later.
  }
  \note<3>{
    \footnotesize
    Input quality is an essential precondition. Distillation has a restricted
    error regime: in our analysis, the errors must be sufficiently sparse and
    have the required structure. An honestly executed distillation circuit
    need not reject arbitrary garbage inputs. Avoid the unconditional claim
    that any input produces either the desired state or rejection. The
    earlier preparation and testing stages must establish a joint promise:
    few bad copies in the batch, except for negligible accepted weight.
    Bounding the error of each individual copy is not sufficient. This is
    the issue to recall on the later Challenges slide.
  }
  \note<4>{
    \footnotesize
    Let $p=1/\mathrm{poly}$ and let $\Phi$ be the ideal resource state. Consider
    a correlated batch
    $\rho=(1-p)\Phi^{\otimes N}+p\sigma_{\mathrm{bad}}$, where the second branch
    contains an arbitrary malicious batch. Every individual marginal can be
    within distance $p$ of ideal, while the whole batch is bad together with
    probability $p$. Distillation has no general guarantee on that branch.
    If it passes the checks with constant probability and produces a wrong
    output, its accepted bad weight remains $\Omega(p)$. The example is a
    failure of the promise, not a claim that every all-bad input is accepted.
    Reliable rejection of the branch would be sufficient; the marginal
    error bound alone does not establish that. We need to bound the joint
    bad-support tail, which the later MBQC and testing analysis supplies.
  }
  \note<5>{
    \footnotesize
    Standard distillation assumes the prescribed operations and checks are
    performed correctly. In our setting the quantum prover performs them and
    may deviate or lie about measurement outcomes. We therefore need quantum
    authentication and verified operations on authenticated resources.
    Authentication addresses malicious execution; the input-quality promise
    still comes from the preparation and testing stages. The diagram now
    uses $\operatorname{Enc}$ as schematic notation for protected resources;
    the red plaintext in one input still represents a bad resource. The red
    process label marks untrusted execution; the output states the desired
    protected-state-or-reject guarantee.
    We will need verified operations on authenticated states; encryption by
    itself is not a verification guarantee. This motivates the next background
    slide, where we can ask who we trust to run the distillation.
  }
